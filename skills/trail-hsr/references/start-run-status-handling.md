# Start Run Status Handling

- `trail start` 现在不再只是建立 `session`；它可能先返回 `ok start.run state=running request=<job_id> waited=<n>`，表示后台 job 仍在执行。此时按异步单例模型原样重发 `trail start`；不要把 running 当作启动失败，也不要立刻换跑 scene 命令。
- `trail start` 终态默认文本首行会返回 `ok start.run status=... session=...`，成功时还会附带 `shot path=...`，并紧跟 `info read_image_first=1`。看到 `shot path=...` 与 `info read_image_first=1` 后，第一动作始终是先读这张原始截图；不要只看 `status` 就盲目继续 scene 命令。
- 需要判断“大世界稳定态”时，优先看本目录下的 `04-world-chaoluguan.jpg`，也就是 `大世界探索态（示例图：朝露公馆）`。这张参考图对应的大世界稳定特征是：左上小地图、右上工具栏、右侧角色栏、左下私聊入口、右下操作区；不要把偶然出现的地点名或附近功能入口当作核心判据。
- 如果返回截图像星穹列车在太空中的启动/过场画面，或仍处于纯黑、淡入这类明显过渡态，就还不是大世界稳定态；不要把这类瞬时过场当成已经可继续推进的正常落点。
- 如果截图已经出现大世界小地图、右上工具栏、右侧角色栏、左下私聊入口、右下操作区，即使角色还在落地光柱里，也可以按大世界稳定态处理；等 Agent 选择下一步命令时，这类短暂落地特效通常已经结束。

## 三态处理

- `status=attached`：说明这次是附着到现有窗口，不等于已经处在可继续推进的大世界。也必须先读返回的原始截图；只有当画面已经清楚满足大世界稳定态，才继续跑 `trail cw enter` 或别的 scene 命令。如果读图后仍无法判断，就先征求用户意见，不要自作主张继续。
- `status=launched_needs_check`：说明启动后还需要 Agent 做视觉确认。先读图；如果画面仍像加载态、黑屏、切换动画中间态，先继续观察，可优先使用 `trail ocr read` 和再次截图，不要额外乱点，也不要盲目继续 scene 命令。
- `status=launched_clicked_enter`：说明启动链路里已经执行过一次进入动作，但这仍不等于已经稳定进入大世界。仍然先读图；如果画面还是加载态、黑屏、切换动画中间态，就继续观察，优先 `trail ocr read` + 再次截图，不要额外乱点。
- 只要后续观察已经确认画面回到了大世界稳定态，就直接沿用这次 `trail start` 返回的 `session` 去执行下一条场景命令；不要为了“再确认一下 attach 正不正常”而重复跑第二次 `trail start`。

## 观察优先于动作

- 只要画面还像加载态、黑屏或动画中间态，就先继续观察，不要把短暂中间态误判成“卡在某页”。
- 观察链路优先级是：原始截图 -> `trail ocr read` -> 必要时再次截图。OCR 用来补充“点击进入”、按钮 box、提示文案等线索，不替代原始图。
- 对 `launched_needs_check` 和 `launched_clicked_enter`，只有在多看一轮后仍能确认页面最终停在 `点击进入` 页，才使用 OCR 坐标 + 点击；不要在加载态里提前乱点。
- 如果最终已经能确认回到了大世界稳定态，再继续对应 scene 命令；若还不能确认是否进入大世界，优先继续观察，或在 `attached` 这类不确定场景下先征求用户意见。
- `trail start` 的职责是把启动链路收口到“可继续判断的当前画面”，不是让 Agent 反复轮询 attach。只要当前 `session` 还有效、而且你已经通过截图/OCR确认界面稳定，就继续后续命令，不要把 `trail start` 当成下一步动作本身。
- 不要把左上角的地点名当成大世界的核心判据，因为地点会变化。
- 不要把恰好出现在附近的功能入口（例如右侧刚好能看到某个玩法入口）当成大世界核心判据，因为玩家不一定停在对应入口附近。
- 还要注意和玩法内探索环节区分：差分宇宙等模式也可能有小地图、角色栏和操作区，但它们的右上工具栏通常更少，且左上的手机入口常会被退出按钮替代。
